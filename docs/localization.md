# English and Russian localization

The existing React app uses a small local catalog, not a framework. English controlled strings are keys; `backend/app/locales/ru.json` is the canonical Russian dictionary imported by both the PDF renderer and frontend. `frontend/src/i18n/store.ts` exposes typed locale/message keys, `tr`, `t`, date formatting and a subscribed language preference; `components.tsx` provides `T` and an accessible EN/RU fieldset. React renders escaped text; no DOM rewriting or user-content translation.

Coverage includes public proposition/navigation, login/registration, onboarding/settings/logout, application navigation, domain/TXT instructions, scan controls, dashboard, findings and controlled risk explanations, task workflow, reports/download feedback, PDF headings/disclaimers, public demo and core errors/empty/loading states. The priority explanation translator recognizes only the exact controlled Phase 05 template and preserves its numeric labels and sorting. It does not recalculate risk. Immutable raw scanner descriptions/check identifiers/evidence and user-entered company/domain/owner/note values remain source text. The old `/preview` is still a design preview, not an assessment.

Preference uses only `localStorage['shieldmate-language']`. No session, token, organization or security record goes into browser storage. Saved EN/RU wins; otherwise browser Russian selects RU, otherwise EN. Storage-denied browsers keep a working memory preference. Switching preserves route and form values and updates document `lang`/title. Unknown keys fall back deterministically to English/source text. Technical acronyms remain recognizable.

UI UTC timestamps format with EN/RU `Intl.DateTimeFormat`, explicit `Asia/Almaty` and the historical date's GMT offset (GMT+6 before the timezone change, GMT+5 in the current scenario). PDF timestamps use locale-formatted explicit UTC. Numeric byte sizes use selected locale; integer counts retain their honest denominators.

Anton and IBM Plex Sans remain the UI families. Existing IBM Plex Cyrillic 400/500/600 faces are served locally; Russian display headings use Plex because Anton does not cover Cyrillic. PDFs embed Liberation Sans regular/bold under its bundled license because ReportLab needs TTF glyph coverage. Automated tests check every catalog character plus Kazakhstan company-name glyphs; selectable text extraction and rendered-page review supplement that check.

To extend: add controlled English/Russian entries to the single JSON catalog; annotate rendered strings with `T`/`tr`; leave customer/raw technical text untouched. Run `npm run i18n:check --prefix frontend`, both test suites and responsive browser QA. The AST checker rejects missing literal/T/ternary references; dynamic rule templates also need behavioral tests and dictionary review. It cannot prove natural translation quality automatically. The shared catalog is the **only backend directory** allowed into Vite's frontend development filesystem scope and Docker frontend build. Customer data/storage and backend source are not exposed.

The Vitest environment explicitly models preference Storage because Node 26's unavailable experimental global getter differs from browser Storage. Browser tests separately verify real localStorage persistence and that it contains only the language key. Non-Chromium browsers, actual assistive-technology reading and device keyboards require subsequent manual verification; native validation messages follow the browser's own language settings.
