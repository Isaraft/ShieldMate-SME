# Phase 08 threat model and risk register

Baseline `e2c58b6`, localhost-first RC. Review includes actual SQLAlchemy scopes/composite foreign keys, sessions/CSRF, migration chain, scanner DNS/transport/worker, deterministic reconciliation, report collection/storage/rendering, React identity boundary and Docker/Nginx. This is an engineering review with adversarial regression tests; no independent human penetration test, linguistic certification or internet-exposure guarantee is claimed. No credible high/critical application bypass was confirmed in this review. That statement describes the inspected/tested scope, not absence of unknown vulnerabilities.

## Security review coverage and limits

Auth uses Argon2id (configured hasher; dummy hash path for unknown users), bounded 12–128 character passwords, cryptographically random session tokens, SHA256-only stored token/CSRF values, constant-time CSRF comparison, timed expiry, revocation and cleanup. Generic login errors do not disclose account existence. No password/email/token values are logged in added checks.

BOLA checks cover organization ownership, domain IDs, scan/domain pair IDs, observation/detail links, finding assessments/history, task/event relationships and report metadata/download. Existing database composite-key and concurrent-owner tests remain; Docker browser negative tests exercise eight cross-tenant resources plus mutation CSRF/Origin. A native BroadcastChannel logout is a UX/privacy response, not an authorization control.

Scanner transport was traced through `socket.connect` to numeric vetted addresses, with Host/SNI retained, default verified SSL context, connected-peer match, fresh DNS comparison and authorization guards. DNS/TLS/header error codes remain honest inconclusive observations. Port selection is code-fixed; redirects never followed; body bytes are not read. The real owned loopback parser test deliberately bypasses target resolution **only by passing its own connected socket**; production target policy still rejects loopback. Fixtures never connect their synthetic public IP. No external scan was run.

Dependency audits report advisory matches for current installed/locked dependencies, not Docker base-image CVE certification. Working-tree text signature secret scanning excludes Git history/binaries and cannot prove absence of every secret. No separate native-language reviewer, penetration tester or user cohort participated. Physical disk exhaustion was not inflicted on the host: SQLite allocation limits and injected I/O failure test actual rollback/publication paths safely.
