# Isolated sample demonstration

`/demo` is a public, read-only guided story; `/preview` remains the separate design preview. The persistent banner and endnote identify **SAMPLE DATA / DEMO — NOT A LIVE ASSESSMENT**, also in Russian. Fictional `Sample Merchant KZ` and reserved `merchant.example` cannot be mistaken for a real authorized customer assessment. Dates are a fixed scenario (2026-10-01 UTC), not current results.

The single canonical typed fixture is `backend/app/reports/demo_snapshot.json`. Assets → observations → three supported findings/priorities → example work → marked PDF all read this dataset. No copies in React, no tenant joins, no enrollment/verification/scan/write endpoints. Public GETs `/api/v1/demo?locale=en|ru` and `/api/v1/demo/report?locale=en|ru` have no authentication or database dependency. The header skips customer identity fetching on this route, even when a visitor has a session. Client fetches omit credentials. Query fields are strictly validated.

`PYTHONPATH=. .venv/bin/python ../scripts/build-demo.py` (from backend) is the explicit **offline maintainer command** to rebuild the fixture from invented observations through the existing Phase 05 pure engine. It does not run at application startup or write into a customer database. Tests verify rule decisions/evidence/severity and ordering against that policy. Fixed IDs/timestamps, three issues (certificate renewal, multiple SPF records and malformed DMARC) and todo/in-progress/done work illustrate the real semantics. The done task's finding is still open. The fixture has zero currently authorized domains and cannot generate a real report.

Sample PDFs use the same renderer and fixture, with DEMO markings on **every page**. They use a separate public endpoint and filename, never customer history. Two locale outputs are cached with a cold-render lock; sample downloads are rate limited per client IP. There is no mutable sample state or fake persistence/reset promise: step controls only change the visible read-only story. Exit links lead to registration/login; no scenario data transfers into a new workspace.

Automated isolation tests replace tenant storage and sockets with failures and still successfully load the public demo. Browser verification while signed in asserts that all demo API requests target the public demo routes and that real report history is unchanged. This demonstrates route separation; it is not a penetration-test claim. QA screenshots and PDFs in `docs/evidence/phase-07/` distinguish LOCAL QA fixture evidence from the public synthetic DEMO. Neither is an actual owned-domain assessment, customer interview or beta-test result.
